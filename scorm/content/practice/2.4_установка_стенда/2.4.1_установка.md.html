Установка и проверка стенда

Скачать 2.4.1_установка.mdНа GitHub

Всё поднимается локально одной командой, данные синтетические, наружу ничего не уходит. На чистой машине путь занимает 10–15 минут, почти всё это время — скачивание образов.

Если вы разворачиваете материалы в JupyterHub банка, читайте вместо этого JUPYTERHUB.md: там про переменные окружения, сертификаты и подключение к реальной базе.

Что понадобится

Что Зачем Как проверить
Docker и Docker Compose база и система дашбордов docker --version
Python 3.10 или новее тетради python3 --version
Свободные порты 5433 и 3000 база и дашборды ./run.sh status скажет, если заняты
Ключ ассистента тетради с GigaChat см. шаг 3

Без Docker тоже можно — см. «Вариант без Docker» в конце.

Шаг 1. Получить папку

git clone https://github.com/wybaeb/bank-analytics-workshop.git
cd bank-analytics-workshop

Если git или сайт репозитория на вашей машине недоступны — та же папка лежит на странице файлов практики сайта материалов: https://wybaeb.github.io/a360/practice_files.html (пароль — тот же, что у остальных страниц). Там архив целиком и каждый файл по отдельности, с указанием, что нужно для какого кейса. Скачайте, распакуйте и продолжайте со второго шага.

Шаг 2. Поставить библиотеки

pip install -r requirements.txt

Пять библиотек: тетради, драйвер базы, pandas, графики и клиент ассистента.

Шаг 3. Заполнить .env

cp .env.example .env

Откройте .env и впишите GIGACHAT_AUTH_KEY — это строка авторизации (Base64) из личного кабинета GigaChat. Там же выбирается область ключа: GIGACHAT_API_PERS для личного ключа, GIGACHAT_API_CORP для корпоративного.

Если под рукой другой ассистент с OpenAI-совместимым интерфейсом, оставьте ключ GigaChat пустым и заполните AI_PROVIDER_URL и AI_PROVIDER_TOKEN — тетради работают одинаково через оба пути.

.env в репозиторий не попадает: он перечислен в .gitignore. Ключ остаётся у вас на машине.

Шаг 4. Поднять стенд

./run.sh up

Команда поднимает два контейнера и ждёт, пока они станут готовы:

  • база postgresql://bank_user:bank_pass@localhost:5433/bank_training — схема и данные загружаются при первом запуске сами;
  • дашборды http://localhost:3000, вход workshop@example.local / WorkshopBI2026!, источник «Учебная база банка» подключается автоматически.

Первый запуск дольше остальных: система дашбордов разворачивает свою внутреннюю базу, это одна-две минуты. Пароли учебные и действуют только на вашей машине — оба сервиса слушают только 127.0.0.1.

Шаг 5. Проверить, что всё сошлось

python3 tools/check_env.py

Скрипт печатает состояние по четырём направлениям и говорит, что делать с каждым непорядком. Значения ключей и паролей он не печатает — только «задана, длина N», поэтому вывод можно показать коллеге или приложить к вопросу.

Если числа строк совпали — данные загрузились правильно, и все числа в материалах у вас воспроизведутся.

Шаг 6. Открыть тетради

jupyter lab

Подойдёт и VS Code с расширением Jupyter, и code-server в браузере — тетради обычные, ядро локальное. Порядок прохождения:

  1. 2.2_разведочный_анализ/2.2.1_разведочный_анализ.ipynb — очистка данных и решения по ним;
  2. 2.3_памятка_sql_и_pandas/2.3.1_памятка_sql_и_pandas.ipynb — одна операция двумя способами;
  3. 2.6_кейс_кредитный_конвейер/2.6.1_конвейер_sql.ipynb — SQL от первого запроса до панели;
  4. 2.7_кейс_отчёт_агента/2.7.1_отчёт_по_запросу.ipynb — запрос словами, отчёт с графиками;
  5. 2.8_кейс_дашборд_агентом/2.8.1_дашборд_агентом.ipynb — агент собирает дашборд.

Кейс карточного бизнеса тетради не требует: он проходится в таблице, инструкция — в 2.5_кейс_карточный_бизнес/README.md.

Что можно проверить, ничего не запуская

node tools/check_apps_script.js   # эталонный скрипт для таблиц даёт ожидаемые числа
./run.sh status                   # что запущено и сколько строк в таблицах

Остальные команды

Команда Что делает
./run.sh status что поднято и сколько строк в таблицах
./run.sh sql консоль к базе
./run.sh dump снять дамп базы в sql/dump/
./run.sh reset снести стенд вместе с данными и собрать заново

Вариант без Docker

Если Docker недоступен, а Postgres есть:

createdb bank_training
psql -d bank_training -f sql/dump/bank_training.sql

Дальше пропишите в .env свои PGHOST, PGPORT, PGDATABASE, PGUSER, PGPASSWORD и запустите проверку окружения. Тетради с SQL и памятка будут работать полностью. Не будет только части с дашбордами — её заменяет любая BI-система, в которую можно вставить SQL: запросы из тетради переносятся как есть.

Если что-то не поднялось

Симптом Обычная причина Что сделать
port is already allocated порт 5433 или 3000 занят поменяйте порт в docker-compose.yml и в .env
permission denied при docker пользователь не в группе docker sudo usermod -aG docker $USER, перезайти
дашборды не открываются минуту-две первый запуск, разворачивается внутренняя база подождать, ./run.sh status покажет healthy
в таблицах ноль строк том остался от прерванной сборки ./run.sh reset
токен не получен у ассистента нет выхода в интернет, не установлены сертификаты или ключ другой области см. раздел про сертификаты в JUPYTERHUB.md
в тетради ModuleNotFoundError тетрадь запущена другим интерпретатором выберите ядро того Python, где ставили requirements.txt

Правило работы с данными

Все наборы в стенде синтетические. В промпты ассистента идут только учебные и обезличенные данные: реальные клиентские выгрузки во внешние сервисы не отправляются. Это правило не про этот стенд — оно про привычку, которая остаётся после практики.
