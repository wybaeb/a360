# Аналитика 360 · артефакты практической части

Публичный репозиторий с материалами для участников корпоративной программы Сбера
«Аналитика 360» (практическая часть, Шаги 1–4, Карпов Курсы).

**Страницы:** <https://wybaeb.github.io/a360/> — закрыты паролем, пароль называется
на вводной встрече и напечатан на слайде с QR-кодом.

| Страница | Что внутри |
|---|---|
| `index.html` | навигация: что где лежит и что сделать до Шага 1 |
| `longread.html` | лонгрид предчтения «Пять ошибок вывода» — теория, вынесенная из занятия |
| `longread_data.html` | лонгрид предчтения к Шагу 1 «Роль данных: категории и критерии ценности» |
| `practice.html` | самостоятельная практика: пять разборов кикоффа, повторяемых в GigaChat |

Выгрузки и готовые отчёты по ним лежат открыто — они нужны и странице практики,
и ссылкам со слайдов, и их подключает JavaScript отчётов, поэтому шифровать их
нельзя. Выгрузки продублированы в `.js` не для красоты: страницу, написанную
GigaChat, участник открывает с диска, а по `file://` браузер запрещает `fetch`
к соседнему файлу — `<script src>` же работает.
От поисковой выдачи весь домен закрыт `robots.txt` (`Disallow: /`), страницы
дополнительно помечены `<meta name="robots" content="noindex,nofollow,noarchive">`.

В репозитории лежит только шифротекст: страницы зашифрованы AES-256-GCM с ключом
из PBKDF2-HMAC-SHA256 (200 000 итераций), расшифровка идёт в браузере через WebCrypto.
Пароля здесь нет ни в каком виде. После первого верного ввода он сохраняется
в localStorage, поэтому остальные страницы открываются без повторного ввода.

## Что где

```
data/          пять синтетических выгрузок в трёх форматах: .js — для отчётов
               (window.DATA), .csv — для Python и Excel, .txt — для вложения в чат
reports/       HTML-отчёты по этим выгрузкам, собранные GigaChat: страница
               подключает соседний .js, считает проверку и рисует график;
               рядом лежат копии .js, чтобы отчёт работал и по ссылке, и с диска
robots.txt     закрывает материалы от индексации
assets/        скриншоты разборов с занятия
build/         сборка: генерация данных, промпты, прогон на GigaChat API, страницы, SCORM
build/runs/    сырые ответы GigaChat со всех прогонов — доказательная база к таблице
               воспроизводимости на странице практики
dist/          SCORM 1.2 пакет для LMS заказчика (без шифрования)
scorm/content/ те же страницы без пароля — исходник пакета
```

## Пересборка

```bash
python3 build/gen_data.py                     # синтетические выгрузки
python3 build/gen_js.py                       # они же в .js (window.DATA) + копии в reports/
python3 build/reference.py                    # эталонные числа (сверка со слайдами)

GIGACHAT_AUTH_KEY=$(secret get GIGA1_GIGACHAT_TOKEN) \
  python3 build/check_prompts.py --runs 3     # прогон промптов, повторный запуск
                                              # доспрашивает только недостающее

GIGACHAT_AUTH_KEY=$(secret get GIGA1_GIGACHAT_TOKEN) \
  python3 build/check_reports.py --attempts 5   # HTML-отчёты: генерация + проверка
                                                # в настоящем браузере, публикуется
                                                # только прошедшая версия
python3 build/check_reports_safety.py          # в отчётах нет обращений наружу

A360_PASSWORD='...' python3 build/build_pages.py   # страницы + гейт + scorm/content
python3 build/build_scorm.py                       # dist/a360_step0_scorm12.zip
```

### Страницы от внешних генераторов

`trainer_tree.html` и `trainer_sample.html` собираются не в `build_pages.py`:
их HTML авторский и целиком лежит в `scorm/content/`. В корень они всё равно
должны попадать через гейт, поэтому перечислены в `STATIC_PAGES` внутри
`build_pages.py` — сборка берёт открытую копию из `scorm/content/`, шифрует
её и кладёт в корень. Содержимое при этом не меняется.

Порядок такой: сначала положить готовую страницу в `scorm/content/`, потом
запускать `build_pages.py`. Новую страницу от внешнего генератора нужно
добавить в `STATIC_PAGES`, иначе сборка остановится: в конце она сверяет
состав корня и `scorm/content/` и не даёт выложить страницу открытым текстом.

Промпты живут в `build/prompts.py` — это единственное место, откуда их берут
и страница практики, и прогон на API. Поэтому текст, который участник копирует
со страницы, — ровно тот, который проверялся.

Цитаты и ссылки на источники теории — в `build/sources.py`; из них собирается
и список источников в лонгриде, и отчёт о проверке для заказчика.

## Про данные

Все выгрузки синтетические, сгенерированы детерминированным PRNG для обучения.
Совпадения с реальными клиентами и сделками случайны. Генератор `build/gen_data.py`
повторяет тот же алгоритм, что считает данные в живых демо кикоффа, — числа
на слайдах и в практике совпадают до последнего знака.
